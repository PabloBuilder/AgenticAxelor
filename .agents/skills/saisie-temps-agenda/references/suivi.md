# Occurrence tracking

Use `scripts/registry.py` with a private, persistent per-user SQLite file outside Git; ask for a private location if none is available. Create a new empty registry only with the user's agreement, and reconcile existing sheet rows first; a fresh or missing registry is not evidence that an event is new. Never store secrets. Local tracking is neither cross-device synchronization nor a shared lock. If the registry is missing or the user changes devices, do not assume an event is new. Compare existing rows and suspend unresolved cases. Warn about possible concurrent writes as required by `SKILL.md`; stop on any detected conflict. Person, date, ticket and duration identify candidates, not an event uniquely.

Record account, calendar, stable occurrence ID (not just series ID), original title, start/end instants and ticket, spreadsheet, tab, row locator, written values and state. Store user-approved ticket or project corrections separately in the target metadata, without altering the original snapshot. For a partially pre-existing entry, record its amount, approved remainder, evidence and all associated occurrence IDs; if exact allocation is unknown, mark it unresolved rather than treating any occurrence as fully imported. Do not disclose the registry in Git or reports. Row numbers can move: verify row contents before relying on a locator; stop if the row cannot be identified.

Use `python <skill>/scripts/registry.py --help` for the CLI. Pass account, calendar and stable event ID; `inspect` uses a JSON snapshot with `title`, `start`, `end`, `ticket`. Before writing, use `prepare` with that snapshot and a JSON target containing `spreadsheet`, `sheet`, `row`, `values`. After writing, read back and compare; only then call `verify`. The CLI does not check Google Sheets itself. On interruption, uncertain response, registry failure or mismatch, retain the pending state, stop and request reconciliation. Never retry automatically: the write may have succeeded despite an error. An intent alone does not prove a write happened.

On later runs compare title, start, end and ticket against the snapshot. Skip verified unchanged occurrences; report changed or missing ones without modifying or deleting their rows. Stop affected entries on ID collision, incomplete access, corrupt registry or concurrent conflict. Never claim cross-device uniqueness without a verified shared atomic mechanism.
